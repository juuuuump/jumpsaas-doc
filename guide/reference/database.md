# Database Documentation

## Overview

JumpSaaS uses PostgreSQL with Drizzle ORM for type-safe database operations. This document covers local development, schema management, and production deployment.

## Tech Stack

- **PostgreSQL** - Production-grade relational database
- **Drizzle ORM** - Type-safe SQL ORM
- **Drizzle Kit** - Schema migrations and push
- **Better Auth** - Auto-generates auth tables

## Database Scripts

```bash
pnpm auth:generate    # Generate Better Auth schema files
pnpm db:push          # Push schema to database (uses DATABASE_URL from .env)
pnpm db:seed:plans    # Seed subscription plans
```

## Local Development Setup

### 1. Start PostgreSQL with Docker

```bash
docker compose up -d
```

This starts a PostgreSQL container on `localhost:5432`.

### 2. Configure Environment

Your `.env` file should contain:

```bash
DATABASE_URL=postgresql://user:password@localhost:5432/jumpsaas
```

### 3. Push Schema to Database

```bash
pnpm db:push
```

This creates all tables defined in `src/db/schema/`.

## Production Deployment

### Push Schema to Production Database

To initialize or update your production database schema without modifying your local `.env`:

```bash
DATABASE_URL="postgresql://username:password@host:port/database" pnpm db:push
```

**Example:**

```bash
DATABASE_URL="postgresql://postgres:yourpassword@production-host.com:5432/jumpsaas_prod" pnpm db:push
```

This temporarily overrides the `DATABASE_URL` environment variable for this single command execution, keeping your local configuration unchanged.

### Important Notes

- [CAUTION] Always backup your production database before running schema changes
- [CAUTION] Never commit production credentials to version control
- [CAUTION] Consider using connection pooling (PgBouncer) for production
- [YOURS] Test schema changes on a staging database first

## Schema Organization

### Auth Schema

Generated by Better Auth at `src/db/schema/auth.ts`:

- `auth_users` - User accounts
- `auth_session` - Active sessions
- `auth_account` - OAuth providers and passwords
- `auth_verification` - Email verification tokens

**Generate auth schema:**

```bash
pnpm auth:generate
```

This reads your auth configuration from `src/lib/auth/server.ts` and generates the appropriate Drizzle schema.

### Application Schema

Define your application schemas in `src/db/schema/`:

```typescript
// src/db/schema/user-profile.ts
import { pgTable, text, timestamp } from "drizzle-orm/pg-core";
import { auth_users } from "./auth";

export const user_profile = pgTable("user_profile", {
  id: text("id").primaryKey(),
  userId: text("user_id")
    .notNull()
    .references(() => auth_users.id, { onDelete: "cascade" }),
  bio: text("bio"),
  createdAt: timestamp("created_at").defaultNow().notNull(),
});
```

Then export from `src/db/schema/index.ts`:

```typescript
export * from "./auth";
export * from "./user-profile";
```

## Making Schema Changes

### 1. Update Schema Files

Edit files in `src/db/schema/` or generate new auth schema:

```bash
# If changing auth config
pnpm auth:generate
```

### 2. Push to Database

```bash
# Local
pnpm db:push

# Production
DATABASE_URL="postgresql://..." pnpm db:push
```

### 3. Verify Changes

Connect to your database and verify tables:

```bash
# Local
psql postgresql://user:password@localhost:5432/jumpsaas -c "\dt"

# Production
psql postgresql://... -c "\dt"
```

## Drizzle Configuration

Configuration is in `drizzle.config.ts`:

```typescript
import { defineConfig } from 'drizzle-kit';

export default defineConfig({
  out: './drizzle',              // Migration files directory
  schema: './src/db/schema/index.ts',  // Schema source
  dialect: 'postgresql',
  dbCredentials: {
    url: process.env.DATABASE_URL!,    // Connection string
  },
});
```

## Database Client

The database client is configured in `src/db/index.ts`:

```typescript
import { drizzle } from "drizzle-orm/node-postgres";
import { Pool } from "pg";

const pool = new Pool({
  connectionString: process.env.DATABASE_URL,
});

export const db = drizzle(pool);
```

## Common Tasks

### Query Data

```typescript
import { db } from "@/db";
import { auth_users } from "@/db/schema";
import { eq } from "drizzle-orm";

// Find user by email
const user = await db.query.auth_users.findFirst({
  where: eq(auth_users.email, "user@example.com"),
});

// Or using select
const users = await db.select().from(auth_users).limit(10);
```

### Insert Data

```typescript
import { db } from "@/db";
import { auth_users } from "@/db/schema";

await db.insert(auth_users).values({
  id: "user123",
  name: "John Doe",
  email: "john@example.com",
  emailVerified: false,
});
```

### Update Data

```typescript
import { db } from "@/db";
import { auth_users } from "@/db/schema";
import { eq } from "drizzle-orm";

await db
  .update(auth_users)
  .set({ emailVerified: true })
  .where(eq(auth_users.id, "user123"));
```

### Delete Data

```typescript
import { db } from "@/db";
import { auth_users } from "@/db/schema";
import { eq } from "drizzle-orm";

await db.delete(auth_users).where(eq(auth_users.id, "user123"));
```

## Troubleshooting

### Connection Issues

If you can't connect to the database:

```bash
# Test local connection
psql postgresql://user:password@localhost:5432/jumpsaas -c "SELECT version();"

# Test production connection
psql postgresql://... -c "SELECT version();"
```

### Schema Out of Sync

If your schema doesn't match the database:

```bash
# Reset local database (WARNING: deletes all data)
docker compose down -v
docker compose up -d
pnpm db:push

# For production, manually drop tables or use migrations
```

### Generate Migrations Instead of Push

For more control, generate migration SQL files:

```bash
# Generate migration
drizzle-kit generate

# Review migration in ./drizzle directory
# Then apply manually or use drizzle-kit migrate
```

## Best Practices

1. **Always use type-safe queries** - Let Drizzle infer types
2. **Define relations** - Use Drizzle relations for type-safe joins
3. **Index frequently queried fields** - Add indexes for performance
4. **Use transactions for related operations** - Ensure data consistency
5. **Validate input with Zod** - Before inserting into database
6. **Never expose raw connection strings** - Use environment variables
